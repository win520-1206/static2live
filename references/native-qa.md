## 原生 Wallpaper Engine（V0.3）

音频实测要核对播放器实际开始/结束时间与截图时间是否重叠。并行调用不保证同期：审批或启动延迟可能让标为During的截图早于声音。没有覆盖播放时段时只记录证据缺失，不能判定宿主响应有或无；一次播放授权仍已消耗，不自动补播。

人物鼠标策略与Shader公式有版本契约；遇到未知policy或公式匹配错误应停止导出/验证并检查安装包版本，不手改policy、重新计算哈希或退回冻结人物来使检查通过。旧版无policy与明确subject-anchored-v1仅作历史兼容，不代表新要求已满足。

用户选择 wallpaper-engine 时先读 [V0.3 实施说明](../docs/V0.3_IMPLEMENTATION.md)，运行 generate --help。调用 `static2live IMAGE --target wallpaper-engine ...`；非标准安装用 --engine-path，合法同结构编辑器模板用 --we-template。不自行拼凑 scene.json 或制造假 .tex，不安装引擎或下载模板。

读 manifest.adapter 的 requested/actual、native-plan.json 的 unsupported 和 validation.native_runtime。没有本机引擎/编译器/模板时保留 Web 并说明降级，不能称原生生成成功。真实编译错误不是成功降级；保留错误产物报告。Glow/Cloud Drift 和局部粒子未原生映射，不能强行宣称等效。

仅显式用户确认的 other 蒙版可加 --native-sway，幅度由 --sway-amplitude-px 控制；默认关闭，不自动发丝/人物分析，不作用整图。模板、着色器、引擎许可与项目 MIT 分开，不将本机引擎资源作为公开示例。

用 `static2live preview-native VERSION` 开独立 QA 窗口，不自动替换桌面或复制到引擎 myprojects。Web browser/visual 与原生分别验收；一端受限不妨碍另一端检查，但不能转移通过记录。实际原生检查加载、鼠标四角、边缘、用户设置的0/100与开关、粒子，以及选用摇摆时的局部变化。实际观察后才 record-native --check load --check mouse --check edges --check properties --check particles（如有摇摆再加 --check sway）--note 观察说明。不能凭启动返回码、单元 mock 或浏览器画面记录原生通过。

无法访问原生窗口时保持 not_tested，报告具体障碍，请用户打开编辑器保持窗口可见后再验收，不假造截图或完成状态。原生与 Web 随机序列/外观不完全相同；记录差异。重新 validate 或修改资源后重验。

继续上次验收前重新列出窗口，匹配当前Manifest哈希对应的window_title；窗口已关闭时不能把聊天间隔或仍有引擎后台进程算作连续运行。实际观察只能支持所见项目：多张时序截图可支持粒子变化，但不能代替属性0/100对照、发梢周期、精确位移测量或10分钟稳定性。完整验收前的分项证据单独记录，不为凑齐record-native而填入未观察的--check。

`preview-native` 的 command_sent 只代表发送命令。未出现QA窗口时先核对实际引擎窗口；必要时从已安装的主入口启动，或请用户打开引擎。终端进程查询与可见窗口矛盾时先核对观察环境，不据此要求用户反复重开。不要直接运行bin/wallpaperui.exe，它会提示UI improperly started；这不是壁纸Shader故障，也不是修改系统或注入软件设置的理由。浏览页选中正确工程后可用“在编辑器中打开”，不要为了打开预览而应用到桌面。若预览面板裁掉发尾，先最大化或调整检查视图，不盲目修改运动幅度；记录实际显示比例。

独立预览现按motion.canvas比例请求不超过960×640的窗口，尺寸写入requested_preview_size，取整可能有一像素误差；不再固定3:2。该字段只是请求，不保证宿主建立窗口或实际客户区一致。用返回标题和实际窗口核对；若Unicode请求未出现，获准的ASCII副本重试仍未出现时停止该通道重试，使用编辑器验证，不把原因归结为已经排除的单一编码问题。保留源版本、当前照片预览及未测状态。

检查preview-native返回的window_title与path_strategy：窗口名带Manifest哈希，避免同版本名混淆。若中文路径在引擎日志中变成乱码并报文件空/不存在，先核对真实文件，再用用户指定的ASCII输出目录或编辑器正常打开复验；已有ASCII短路径仅在确认指向同一文件时使用。不重命名用户目录、不修改Windows编码/安全设置、不把空预览当成功。

也可显式使用`preview-native VERSION --qa-cache ASCII_DIR`，只复制Manifest跟踪且哈希正确的原生资源到独立新目录。先说明副本包含壁纸图片并会保留，不自动清理；目录必须独立且可写。不写入引擎myprojects，不把副本生成或命令发送当作实际加载。用户停止界面操作后不要自行恢复。

编辑器打开已有工程时须保留整个 wallpaper-engine 文件夹的资源结构。可让用户将整目录复制到引擎 projects/myprojects 的独立新目录，再从已有项目打开；不要把 project.json 拖到“创建壁纸”，否则可能创建空场景。左侧必须出现生成的图层后才验收。发现整图平移、粒子不可辨或属性失效时记 failed/warning，不把控件勾选或结构通过当作动态生效。

若“文件→打开”只列出myprojects的旧工程，不选旧项目冒充当前输出；需要工程目录外写入或复制时先确认范围及写权限，不把仅允许窗口操作理解为允许安装/应用。独立QA副本与引擎项目目录副本是不同操作。检查更宽/更窄窗口时同时核对主体构图；无透明边缘不代表没有裁头/裁发尾，不能仅靠最大化判定适配通过。

红色/黑色错误画面须检查本次原生 Shader 编译日志；资源编译器成功不等于 GPU Shader 编译成功。强度控件即使显示未使用警告，也要分别实测0/100与开关，保留警告及实际结果，不凭警告推断全部失效或凭控件值推断通过。

属性对照应区分普通编辑画面和“运行预览”：本机实测零粒子强度在编辑画面仍见颗粒，运行预览后才观察到消失。保留即时与后续结果，未测过渡时间时不宣称即时生效或绑定失败。编辑器可能自动保存QA副本；结束时恢复本次测试改过的默认值，并核对副本与源输出的差异，不把初次复制哈希继续当作已编辑副本的当前哈希。

V0.3必需验收项失败时先修复、生成独立新版本并复验，不宣布V0.3完成或提前实现后续版本。粒子开启样例须在目标引擎、实际显示比例下辨认出多处颗粒随时间移动，并实测关闭/零强度后隐藏；仅存在粒子JSON、模糊截图差异或静态亮点不足以通过。先核对打开/应用的工程路径与版本，避免同名旧工程混淆。用户报告与先前验收矛盾时重新核验，保留旧结论与修订记录。

粒子资源存在但不可辨时，分别检查尺寸缩放、透明度/淡出、亮背景混合方式、发射范围及人物覆盖。暖尘采用透明混合保留亮背景对比，不把增加数量当作唯一修复。验证正在执行的安装包确实含新代码；修改源码后旧 wheel 不会自动更新。交付时明确新工程名称/路径，并加载该版本复验，不能只生成新目录就声称用户当前壁纸已修复。

原生 QA 结束后恢复本次交付工程，再核对标题、路径和开启效果的时序画面；无粒子的隔离样例不能留作最终展示。记录各样例验证的功能，不把分项通过挪给另一个未完整验收的版本。

原生音频开启时检查导出 project.json 的 general.supportsaudioprocessing=true 与 SceneScript 注册是否一致；不能依赖编辑器首次打开后自动补标记。关闭音频的导出不得从模板继承该能力。官方[音频故障排查](https://docs.wallpaperengine.io/en/web/audio/visualizer.html)说明了这一工程标记；该页针对Web，原生证据须另外来自当前SceneScript和宿主观察。标记存在、播放命令成功或模拟频谱单测通过都不能证明真实音频响应。一次授权测试后若声音/画面不明确，记录时间与配置差异，保持未测或未通过，不自行加音量、重播或修改输出设备。

局部摇摆看不出来时，区分对象内部纹理和轮廓是否真的变化。逆向 UV 采样若蒙版恰好止于轮廓，会把外侧像素钉住；保持用户原始蒙版不变，由适配器按位移上限生成有限外扩、柔边的采样蒙版，再检查轮廓、邻近背景及零强度/关闭对照。不能靠整图移动或无限扩大蒙版代替局部运动。

脸部稳定但鼠标移动时头发与人物割裂，仍判人物连续性失败。先区分时间发梢动画与鼠标深度位移：只锁脸、让相邻头发按不同深度移动会撕开衔接。历史修复subject-anchored-v1曾用独立pointer guard合并person/hair/cloth/protected及有限采样留量，冻结人物鼠标形变；该方案已被下述v2取代，不能用于新导出的验收目标。原发梢权重/时间动画不改，覆盖板使用同一pass。Web及原生高级runtime复用同一guard，打包进深度纹理G通道而非Alpha，保持R深度和不透明Alpha；不新增纹理槽，不将人物guard误用于音频/Shader的面部保护。原生runtime使用单独_subject资源名，旧资源保留。各分支实际GPU/宿主观察仍分别验收，不能由合成Web像素通过推定音频或照片通过。它不是背景补全或分层重建。旧输出保持原策略；必须加载新Manifest，左右鼠标及停鼠标分别观察，确认无割裂且仍有发梢轻摆，不能以降低全局强度或旧版脸部认可替代。

低对比照片或宽条纹不足以判断微位移时，可用程序化高对比网格隔离诊断：`examples/make_native_runtime_demo.py --output NEW_DIR --shader wave --diagnostic-grid --amplitude-px 3.5`。该640×360测试夹具默认无音频、无粒子/视差，幅度仍受短边1%限制；这不是用户照片推荐参数。检查局部线条随时间变化、外围与保护区保持直线，再对照关闭与开启但零强度。只有网格通过，不能推定发梢主观可辨、其他Shader或真实音频通过；不改用户照片参数来迎合诊断。纹理缩略图初次显示X后可能异步完成，应刷新并核对资源后再判缺失。需要复制到引擎目录时仍须明确授权、备份，结束后恢复照片工程。

鼠标视差轻到难以分辨时，另用 `examples/make_native_parallax_demo.py --output NEW_DIR` 生成网格、左右黑/白深度和中央保护块，再调用现有CLI：`static2live generate --input NEW_DIR/grid.png --depth-map NEW_DIR/depth.png --regions NEW_DIR/assets/regions.json --config NEW_DIR/config.yaml --output OUTPUT_DIR`。这是显式合成算法测试，绝非真实模型深度，不能替代照片推理验收。它禁用时间动画、粒子、发梢和音频，仅以短边1%幅度隔离鼠标：左右移动应方向相反、右侧近景位移大于左侧远景、中央保持；四角不露空，关闭或开启但0%时恢复直线基线。动作后截图可能早于鼠标/布局完成，应再次刷新确认终点，不能把中途帧当稳定结果。网格的硬深度/保护边界会有刻意的折线，不把它误报为真人发丝裂缝；照片边缘审美仍须独立验收。

上述subject-anchored-v1是历史失败方案：用户实际反馈人物不动且背景太弱，鼠标效果不可辨。新导出使用subject-rigid-v2，把来源化人物联合区域的鼠标深度权重设为统一非零0.85，区域外仍按原深度，有限外扩柔边衔接；脸部只随人物刚性平移，不承受局部深度拉伸，发梢时间动画独立保留。Web与原生高级runtime复用深度G通道支持，普通人物分支复用独立guard纹理。旧策略导出继续按原契约验证，不追改文件。新旧策略结构通过不代表实际视觉通过，必须复查非零鼠标响应、人物内部连续性、面部形状及停鼠标时的发梢。

该例程的显式--subject-anchor增加更大的合成person框和内层保护框，以零强度warm_glow选择组合runtime分支，不启用音频。用于区分完整人物一致平移、完整冻结及仅锁脸，不能继续把中央人物完全静止当新策略的通过条件。还应检查无发梢、无高级效果、仅person区域的原生导出：启用视差时也须走人物pointer guard，不能退回普通深度分支。旧无pointer_policy工程保持历史契约，结构兼容不代表旧版已有此修正。

霓虹色偏可见但呼吸亮度难辨时，用同一夹具的 `--shader neon_pulse --diagnostic-flat --amplitude-px 0`，再以其demo.png、assets/regions.json和config.yaml调用generate。深灰纯色消除纹理干扰，零位移排除红蓝采样偏移；不改Shader公式、不启用音频。检查运行中局部颜色在不同时刻明暗变化、中央保护块/外围保持基线，并对照关闭和开启但0%。纯色通过只支持该样例的亮度分支，不能证明非零色散、精确周期/帧率或照片效果。--diagnostic-flat与--diagnostic-grid互斥，均拒绝覆盖已有输入目录。

宽屏裁头时先读[输入取景](../docs/INPUT_FRAMING.md)，确认用户愿意裁切还是留边，不把切换预览比例当作修复。换同一路径工程后检查图层中心/画布尺寸及新资源，不只看相同标题或缓存缩略图。若出现暗色遮罩且仍为旧尺寸，刷新及正常关闭面板未恢复时停止重复点击，请用户重新打开明确的QA工程；不强杀或假报新版本通过。

菜单显示16:9不保证当前渲染面板的实际比例就是16:9。可在不改场景参数的前提下调整面板分隔线，再等刷新观察；记录实际面板与源画布比例。拖动瞬间的挤压帧不是稳定构图或动画变形证据。

逐个验收几何原语时，用独立合成网格工程区分局部运动、保护区和外围，分别观察关闭、开启但0%、恢复默认强度；某一原语通过不代替其余原语。若需替换同一路径QA资源，先正常关闭编辑器，确认窗口消失，备份并复制后再从新编辑器载入，避免把缓存旧工程当作新资源。该顺序是本机遮罩问题后的保守做法，不是已证明的故障根因。恢复默认值后复核资源哈希；布局拖动后的黑色过渡帧须等稳定刷新，不能直接记成采样露边或忽略持续黑屏。

V0.3基础Adapter本身不含自动发梢、表情、精细保护、背景补全、MP4 或完整编辑器；人物与编辑开发能力见[开发工作流](development.md)。其他参考：[V0.2 实施说明](../docs/V0.2_IMPLEMENTATION.md)、[许可](../docs/MODEL_LICENSE.md)、[设计](../docs/V0.2_PLAN.md)。
