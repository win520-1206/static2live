# V0.2 两模式设计与实施边界

状态：Lite / Smart 已实现，软件升级为 0.2.0；旧输出保留。下文保留设计依据，实际命令与验收见 README 和 V0.2_ACCEPTANCE.md。

依据原设计规格第 34 节：新增 Segmentation、Rain、Snow、Fog、Dust、Glow、Cloud Drift、Particles。延续本地优先、生成阶段离线、薄 skill、版本化输出和四态验收。

## 模式定义

| 项目 | Lite（默认） | Smart |
| --- | --- | --- |
| 分割模型 | 不下载、不依赖、不要求安装分割依赖 | 显式准备一个本地分割模型 |
| 区域来源 | 基础手画、导入蒙版、可选简单规则 | 模型预测，可再人工修正 |
| 运行 | 区域处理和效果播放均离线 | 权重准备后，识别与播放均离线 |
| 来源记录 | manual / imported / rule | model，修正后追加修正来源 |
| 识别声明 | 不宣称规则是可靠语义识别 | 是模型预测，不保证准确 |

“Lite 不下载模型”指 Lite 的区域识别流程不新增模型，不只是偷偷复用 Smart 缓存。视差沿用 V0.1：使用已有本地深度模型，或由用户提供深度图；Lite 不自动准备深度模型。缺少两者时不能以规则假造深度。仅制作不含视差的程序化效果时，允许显式关闭视差，不要求深度图或任何模型；该路径不得声明深度或视差已验收。

Smart 缺模型时明确报错并提示准备命令，不自动联网，也不静默回退到 Lite。用户主动切换模式才改变区域来源。用户选择 Smart 并不等于同意首次下载模型。

## 提前加入的基础区域绘制

这是用户已确认的版本调整：把原 V0.5 的最小标注能力提前到 V0.2，但不实现完整标注编辑器。

- 支持画笔、擦除、区域类别选择、蒙版预览、清除和保存；Smart 结果也能用同一套工具修正。
- 类别包括人物、天空、水面、云层、发光区域、其他；名称用于效果选择，不表示手画结果经过自动识别。
- 画布按原图比例显示，以归一化的左上原点坐标映射到统一导出尺寸，窗口缩放不能改变蒙版对应位置。导入蒙版严格校验尺寸/坐标，不猜测错位。
- 按区域保存独立蒙版，保留重叠关系与来源；不强制把人物和发光区域等不同用途塞进一张互斥类别图。分类标签图另外按标签表处理。
- 保存标注只生成独立标注资源，不直接修改已验收壁纸、原照片或旧 Manifest。重新调用生成流程才应用修改并分配新版本。
- 不做完整项目时间线、图层编辑、复杂选区、背景修复、五官解析或发丝标注算法。

## 简单规则的边界

规则是可选的候选区域建议，例如用户限定范围后的颜色阈值或亮度阈值。默认不把“蓝色”等同天空、不把高亮自动等同灯、不把深度阈值冒充人物识别。必须提供预览与调整，用户确认后才用于区域限定效果，记录规则及参数和确认状态。未确认候选不能悄悄生效；没有区域时不硬编码当前照片坐标。

## 拟定接口

```powershell
# V0.2 已支持
static2live image.jpg --mode lite
static2live image.jpg --mode smart
```

配置增加 `mode: lite | smart`，默认 lite，仍遵循 CLI > 用户配置 > Preset > 默认值。区域资源入口和基础绘制子命令在实现时一并定义、写入 help 与中文说明；无区域时提示如何绘制/导入，不假装已有识别结果。全画布效果可明确选择全画布，不要求无意义的蒙版。

两种模式共享区域资源格式、Motion Planner、Motion Manifest、Web Renderer、效果参数及 Validator，不维护两套渲染实现。Renderer 不关心区域来自模型还是人工，只消费已经验证的 Manifest。

## 实施顺序

1. 先实现 Lite 区域资源、基础绘制/导入和规则候选确认，再增加 Smart SegmentationBackend。模型显式准备并记录 revision、许可、文件哈希；缺失报错，不把深度阈值或颜色阈值冒充语义分割。分类标签用最近邻缩放，统一 EXIF、尺寸与坐标；软蒙版与类别图使用各自正确的缩放策略。
2. Motion Manifest 升级为 0.2，记录语义资源、效果类型、区域、参数、随机种子；验证和渲染继续支持已有 0.1 输出。不得让新版 Validator 拒绝正常的旧版本。
3. 程序化雨、雪、尘、雾和辉光，固定 seed、有限预算，分布覆盖全画布而非固定窄条。允许开关及明确单位，系统减少动态偏好关闭时间动画和视差。静态降级继续提示，不能宣称效果通过。
4. 区域选择使用语义蒙版或显式用户蒙版，不硬编码当前照片的坐标。人物分割只能支持人物区域排除，不能宣称精细脸部保护。Glow 使用指定区域的亮度变化，不自动认定所有亮像素都是灯。
5. Cloud Drift 只在确认有云层的蒙版上开启；分割模型的 sky 类不等于 cloud 类。无云蒙版时不把整块天空或人物背景强行扭动，不把背景补全列为已实现。
6. 扩展 Preset、CLI、配置 Schema、Validator、中文说明和薄 skill。Renderer 只消费 Manifest，不重复图像分析；安装包资源保持可移植，双击 HTML 离线播放。

## 模型选择与准备

候选轻量模型为官方 `nvidia/segformer-b0-finetuned-ade-512-512`，用于多类别语义分割，不用于人像细粒度解析。其模型卡 license=other，并指向 NVIDIA SegFormer 许可；不能沿用深度模型的 Apache-2.0，也不能将模型权重标为本项目 MIT。

参考模型卡：https://huggingface.co/nvidia/segformer-b0-finetuned-ade-512-512

新增模型下载须单独得到用户允许，先核实和记录模型许可再显式准备。生成不得联网，照片不上传。模型不准备时可实现和测试用户标签图路径，但真实模型验收必须记为 not_tested，不能据此报告完整完成。

候选模型须验证其实际类别表对天空、人物、水面等目标的覆盖；未支持的类别明确标记不可自动识别，不能仅重命名标签伪造能力。Smart 不包含人像细粒度解析，不保证识别脸、眼睛、头发。

## 验收

- V0.1 回归：旧 Motion / Project Manifest、旧输出、深度视差、CLI 参数优先级和覆盖安全。
- Lite：分割依赖和缓存均不存在仍可工作，任何路径不触发模型下载；绘制/擦除/保存/重新导入一致，缩放后坐标不变；规则候选必须确认，来源与参数可追踪。无模型的效果路径不声称深度通过。
- Smart：只读取已准备分割权重；实际自动识别和人工修正可验证，缺模型不回退，模型类别表与输出对应；分割模型权限与真实验收单独报告。
- 分割：真实 CPU 推理、分类范围与标签表、蒙版尺寸和坐标、用户标签图错误输入、模型缺失和哈希损坏、原图 RGB 保真。
- 效果：固定 seed 重复结果，类型与单位合法，启用/关闭绑定，零强度静止，粒子空间分布与可见性，区域外不受局部效果影响。
- 浏览器：file:// 资源加载、WebGL、控制台、鼠标、时间变化、窗口缩放、四角边缘、减少动态和静态降级；真实照片加自然场景的视觉观察不能用返回码替代。
- 输出：继续新增版本、不覆盖旧样例。结构、浏览器、视觉分开报告；未执行为 not_tested，缺适用区域为说明性 warning，而非伪造通过。
